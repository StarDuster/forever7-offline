# 构建、使用与源码目录

## 输入和工具链

- 官方原 APK：网易 Android 1.96.455，versionCode 10960455，1,277,771,744 字节。
  SHA-256：`12e57f77059f7f3964585f3a615410f3f9625101d885883cd4de4397f490c503`。
- 固定 Project7 组件：57,258,978 字节，SHA-256：
  `ccbde188251c68eb23a4af1d0b6aef1946236d527d2a70f30058277e5a7b7a0d`。
- Python 3.11+、本机 C 编译器、JDK 17、Android SDK API32、build-tools37.0。
  Python 依赖列在 `requirements-offline.txt`，工具链由本机提供。

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements-offline.txt
```

## 构建

普通用户使用 [README](README.md) 中的命令；默认后端 `project7` 无需显式填写。
`legacy` 是保留的对照构建路径。

- `--render-mode png` 使用原版 PNG 界面兼容路径；默认 `astc`。
- `--offline` 主要约束 legacy 的 `script.npk` 缓存。Project7 的 official640 脚本重建
  始终本地，但组件解析仍可能联网；全离线请使用依赖就绪包或显式
  `--component-offline-input`。
- `--prepare-only` 只准备构建输入，不执行 D8、组装或签名。

完整入口执行编译、D8、组装、签名和 16K 对齐，最终产物是一个 APK。
依赖就绪包中的 `.offline-deps/` 组件会被发现并校验；纯源码包通过
`--component-offline-input` 提供同一固定组件。

### 签名

签名身份完全由构建参数决定，产物就是那把钥匙签出来的。

- 不传 `--keystore`：使用 `build-dir` 里的开发密钥 `signing/offline-dev.p12`，
  密码首次构建时随机生成到 `signing/password.txt`（0600）。默认 `build-dir`
  是 `.offline-build/`，所以同一份缓存里连续构建的证书保持不变；换
  `build-dir` 或删掉该目录就等于换了一把钥匙。
- 传 `--keystore <p12>`：必须同时给 `--key-password-env <变量名>`，密码从该
  环境变量读取；文件缺失或变量为空会直接报错退出。
- `--key-alias` 默认 `forever7-local`；未指定的密钥按 PKCS12、RSA 2048、
  3650 天、`CN=Forever7 Local Development` 生成。
- `--expected-cert-sha256` 在发布前比对证书指纹，不匹配就失败，用来锁定
  某一份固定签名身份。

Android 只允许同证书覆盖安装。用另一把钥匙构建的 APK 需要先卸载旧包
（会清掉本机存档），或者用同一 `--keystore`／同一 `build-dir` 重建：

```sh
F7_KEY_PASS="$(cat local-checkpoints/signing/password.txt)" \
  .venv/bin/python offline/tools/build_offline_project.py originals/forever7-netease-83.apk \
  --keystore local-checkpoints/signing/offline-dev.p12 --key-password-env F7_KEY_PASS
```

## 源码目录

```text
offline/current/       当前离线业务、UI、资源准备、单包启动
offline/runtime/        legacy 平面运行时
offline/tools/          构建、导出、打包、资源与 legacy 工具
project7_bridge/        Project7 DEX/脚本注入、RPC/Store 兼容适配
upstream/project7/      固定组件 pin 与官方资源清单来源
runtime/                内嵌启动边界文件
tests/                  测试
```

Java 包名、内嵌 Python2 模块名和 Project7 组件协议保持不变。

## 首次启动与素材

安装 APK 后启动游戏，本地身份、存档和收藏自动初始化。首次准备界面优先读取已有缓存，
缺失素材从官方 CDN 获取。固定素材版本为官方640：36个NPK、276个raw，共8,010,923,732字节。
下载或导入后按固定清单校验大小和 SHA-256，资源完整后可断网游玩。

准备页面提供：

- **选择本地资源 ZIP**：导入按固定清单相对路径组织的资源文件。
- **重试下载 / 完整检查**：重新下载缺失文件或检查缓存。
- **备用素材源设置（可选）**：填写提供相同路径、固定版本文件的 HTTPS 根目录。

私有存档与素材缓存保存在应用数据目录，构建项目的 Git 和纯源码导出均排除这些文件。

## 游戏功能

本地处理身份登录、存档、抽卡、剧情进度、战斗和结算；复用 Project7 的业务实现，
由单包生命周期组件启动本地服务。首次进入复杂界面时会加载相应模型和动画。

收藏目标保留140名神器使、494套服装和1900组影装；原版角色列表、模型、换装、染色、
影装详情及抽卡界面使用原资源。初遇池从公开菜单隐藏，已有卡组数据保留；历史池使用原版
可滚动列表。

## 离线背包编辑

进入游戏设置，点击 **背包编辑**。在“道具 / 货币 / 影装”中选择类别，在左侧按名称或 ID
查询并选择条目，右侧显示图标、当前持有量和修改方式。

- 普通道具和货币提供“设置总量”和“增加数量”；普通道具可设置为零。
- 单次数量输入范围为0至1,000,000，最终余额受原引擎整数范围校验。数量框可直接点按输入
  （只接受数字，失焦后钳制到范围内），`−`/`+` 支持长按加速。
- 列表按页查询（每页50条），底部提供“上一页 / 第 N 页 / 下一页”，可浏览完整目录。
- 影装选择原版品质后点击“生成影装”，每次1至100件，保留现有装备与全收藏记录。
- “快捷”页提供一键发放：清空2018/2019情书（把两组“复刻情书”候选年份归零，用于恢复兑换；
  其余年份不动）、解锁情书(保留兑换)（留下 2018/2019 两组给“复刻情书”选择，其余年份全开）、
  全部情书（326 条，并把复刻/2020/2021/昔日/往日情书各补到 99）、全部礼物、全部碎片、
  全部 CG（分批写入档案的 `cgs` 解锁列表）、补满全部货币。每次点击是带收据的原子编辑；
  CG 按 64 条一批串行提交，丢回包时可安全重发。快捷行动按数量自适应行高，始终留在面板内。
- “卡池开关”列出抽卡表内除常驻池（记忆隙间、影装映射、友情链结、初遇隙间）以外的全部卡池，
  默认全部关闭；只有在此勾选并重新进入白夜馆后，对应卡池才会出现在抽卡界面。
  影装精选/家具池同样由该清单控制。
- 保存后保留当前选择并刷新持有量；按钮皮肤、道具图标和品质颜色使用原版资源。
- 请求未确认时，使用“核对上次操作”核对同一次操作；记录按本地账号分别保存。
- 战斗或未完成的周目结算期间，完成当前流程后再编辑。

每笔修改与防重收据一同原子保存。每个账号保留最多4096笔编辑收据；达到收据容量或
8 MiB 存档预算时会拒绝新修改并保留已有数据。

官方原数据中的未发行条目：神器使46（琉璃）、125（追光·幽桐）带原版 `hero_forbid`
标记，原模型10048、10176 在固定资源中缺失；服装10080、10081缺少发行标记，3D模型
30141、30142存在，部分2D卡面、头像和图标缺失。这些收藏记录保留，缺失模型在创建前
处理，并使用可用的原信息或2D展示。
